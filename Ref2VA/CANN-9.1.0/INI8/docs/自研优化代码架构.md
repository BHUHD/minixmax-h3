# MiniMax-H3 Ref2VA INT8 · 自研优化代码架构

面向开源开发者：说明 **CANN 9.1.0 / Atlas 800I A3 / 16 die** 上 Ref2VA INT8 推理栈如何组织、如何把 Comfy/GPU 路径落到 NPU，以及关键优化落在哪些文件。

| 项 | 值 |
|----|-----|
| 目录 | `Ref2VA/CANN-9.1.0/INI8/` |
| 镜像 | `minimax-h3:ref2va-cann9.1.0-int8-v1.1` |
| 推理包 | `runtime/src/h3_npu/` |
| HTTP API | `runtime/api/` |
| 默认端口 | `8080`（`partition=ref2va`） |

相关文档：`INT8_v1.1.md`（相对 v1.0 修复）、`INT8_16die_deploy_guide.md`（部署与硬件）、上级 `README.md`（启动与耗时数据）。

```text
INI8/
├── Dockerfile.v1.0 / Dockerfile.v1.1   # v1.1 = FROM v1.0 + 覆盖干净 runtime（非 docker commit）
├── docker-compose-v1.1.yml            # 生产一键启动

│   ├── analyze_metrics.py
│   └── entrypoint.sh                  # → runtime/scripts/entrypoint_serve_api.sh
├── docs/
└── runtime/                           # 打进镜像的核心
    ├── api/                           # FastAPI Worker（Gateway 对接）
    ├── scripts/                       # serve 拉起、API 入口
    └── src/h3_npu/
        ├── pipeline/                  # generate / serve / partition
        ├── model/                     # DiT / TE / VAE
        ├── modules/                   # QuantLinear
        ├── ops/                       # INT8 Cube / NVFP4 / FA / gather
        ├── load/                      # safetensors 流式加载
        └── runtime/                   # HCCL dist / H2D / metrics / device
```

**镜像内路径约定**

| 宿主机 / 构建 | 容器 |
|---------------|------|
| `runtime/src` | `/workspace/src`（`PYTHONPATH`） |
| `runtime/api` | `/workspace/api` |
| `models/ComfyUI/INI8/Ref2VA`（挂载） | `/models/h3_quant` |

| 邮箱目录 | `/workspace/out/h3_serve/` |

权重**不**打进镜像，必须 compose 挂载。

## 2. 端到端调用链（开发者必读）

```text
docker compose → entrypoint_serve_api.sh
                 ├─ NPU serve（16 进程常驻）
                 │    launch_generate.py
                 │      → h3_npu.pipeline.generate_worker
                 │         pin die → init_hccl → load DiT → prewarm → _serve_loop
                 └─ FastAPI（rank0 旁路）
                      POST /v1/tasks → TaskWorker → serve_bridge 写 job.json
                      ← serve 写 DONE / progress.json ← run_generate
```

### 2.1 FastAPI → 邮箱

| 文件 | 职责 |
|------|------|
| `runtime/api/app.py` | `/health`、`/v1/status`、`POST/GET /v1/tasks`、下载 video |
| `runtime/api/worker.py` | 串行执行；mock / 真实 mailbox |
| `runtime/api/serve_bridge.py` | `submit_to_mailbox` / `wait_mailbox_done` / `read_progress_file` |
| `runtime/api/storage.py` | 任务目录、TTL、tombstone（重启后旧 task 410） |

`job.json` 关键字段：`id/steps/seconds/height/width/out/prompt/seed/task/ref_images/ref_videos/ref_audios`。  
**始终写入 ref 列表（可为 `[]`）**，避免常驻进程沿用上一单参考。

### 2.2 generate_worker 邮箱协议

| 文件 | 含义 |
|------|------|
| `ready.{rank}` → `READY` | 16 die HCCL + DiT 常驻就绪 |
| `job.json` | API 投递 |
| `ack.{rank}` | 各 rank 认领同一 `id` |
| `done.{rank}` → `DONE` | 成功（`DONE` 内容 = task_id） |
| `FAILED` | 拒绝 / 异常文案 |
| `jobs/<id>/progress.json` | 阶段进度（encode/dit/vae/audio/mux） |
| `jobs/<id>/output.mp4` + `output.metrics.json` | 成品与精细耗时 |

实现：`runtime/src/h3_npu/pipeline/generate_worker.py` 中 `_serve_loop`。

**注意**：serve 结束汇合用文件系统 `done.*`，**不要**在 rank0 写 mp4 时再打 HCCL `barrier`（易触发 SDMA 507035）。见 `generate.py` 尾部 `H3_SERVE=1` 分支。

### 2.3 单次推理主函数

`runtime/src/h3_npu/pipeline/generate.py`：

- `load_dit_to_npu`：加载 INT8 DiT 到各 die HBM（仅启动/worker 初始化）
- `run_generate`：TE → Ref 编码 → noise → DiT 采样 → VAE → Audio → `write_mp4`

任务模式由 `pipeline/partition.py` 的 `resolve_generation_mode` 决定：

| `task` / 参考 | 模式 |
|---------------|------|
| `t2va` 且无参考 | 纯文生，空 ref，不注入 `<Picture>` |
| `ref2va` / `auto`+有参考 | 多模态参考 |
| `auto`+无参考 | 等价 t2va（Ref2VA 权重仍可用） |

## 3. 推理流水线阶段

对应 `run_generate` 时间线（metrics tag 同步写入）：

| 阶段 | 代码入口 | metrics / 日志 |
|------|----------|----------------|
| 1. TE | `model/qwen3_te.py`：`encode_text_npu` | `te_encoded`；`[te] encoded in Xs` |
| 2. Ref 条件 | `generate._encode_ref2va_conditions` + `_broadcast_ref2va_payload` | `refs_encoded`；t2va 跳过 |
| 3. Noise | CPU `float32` `randn` → cast `bf16` | 对齐 Comfy `prepare_noise` |
| 4. DiT | `model/dit.py` + `res_multistep` / euler | `step_k`、`dit_done` |
| 5. Video VAE | `model/video_vae.py` decode | `vae_decoded.vae_s` |
| 6. Audio VAE | `model/audio_vae.py` 默认 **CPU** decode | `audio_decoded.audio_s` |
| 7. Mux | `write_mp4`（x264 + AAC **128k**） | `video_written` → dump metrics |

可选 **progressive**（`H3_PROGRESSIVE`）：多分辨率 stage + latent upsample；生产 compose 默认 `0`（单阶段全分辨率）。

TE∥Ref：`H3_TE_RANK0_ENCODE=1` 时 rank0 可不切 TE 层，用线程并行跑 ref encode（`generate.py` 中 `enc_thread`）。

## 4. 模型与算子栈

### 4.1 DiT（INT8 ConvRot）

| 组件 | 路径 |
|------|------|
| 结构 | `model/dit.py`：`MiniMaxH3DiT` / `DiTBlock` / `Attention` / `MLP` |
| 权重 | `diffusion_models/minimax_h3_ref2va_pruned_int8_convrot.safetensors` |
| 加载 | `load/safetensors_quant.py` + `runtime/h2d.py`：`dit_blocks_to_npu` |
| 线性层 | `modules/linear.py`：`QuantLinear` |

序列布局 Ref2VA：`[text | ref | audio | video]`；t2va 无参考时退化为 `[text | audio | video]`。

### 4.2 INT8 Cube / NZ（吞吐核心）

| 文件 | 作用 |
|------|------|
| `ops/int8_convrot.py` | `pack_int8_weight_cube`、`int8_convrot_linear`；W8A16 / W8A8 |
| `modules/linear.py` | `prepare_cube()`：H2D 后一次性 pack |
| `runtime/h2d.py` | 遍历全部 `QuantLinear.prepare_cube()` |

要点：

1. `H3_NPU_INT8_NZ=1` → `npu_format_cast(..., 29)` 得到 FRACTAL_NZ 权重。
2. **禁止每步** `.t().contiguous()`（否则每步拷贝约数十 GiB）。
3. 优先 `npu_weight_quant_batchmatmul`（BF16 act × INT8 weight）。

### 4.3 NVFP4 Text Encoder（语义正确性核心）

| 文件 | 作用 |
|------|------|
| `model/qwen3_te.py` | Qwen3-VL 前 50 层；`format_ref2va_prompt_multimodal` |
| `ops/nvfp4.py` | `from_blocked` / `dequantize_nvfp4(_host)` / `nvfp4_linear` |

**v1.1 关键修复**：`weight_scale` 存盘为 cuBLAS `SWIZZLE_32_4_4` 布局，反量化前必须 `from_blocked` 还原逻辑二维。缺此步时 TE 隐状态与 Comfy 几乎无关（cos≈0），零参考文生会严重跑偏；有参考时视觉条件掩盖问题。

层并行：`_layer_range` 按 rank 切层；激活 `broadcast` 到各 die。

### 4.4 Attention / FA

| 文件 | 作用 |
|------|------|
| `ops/fa_h3.py` | `h3_attention_bnsd`；生产默认 `H3_FA_BACKEND=infer_v2` |
| `dit.py` `Attention` | Seq Parallel：本地 Q + `all_gather_kv` 后 FA |
| `ops/gather_fa.py` / `runtime/dist.py` | gather 实现：`broadcast` / `into` / `list` |

`infer_v2` 走 `npu_fused_infer_attention_score_v2`（BNSD）。

### 4.5 VAE

| 模态 | 文件 | 备注 |
|------|------|------|
| Video | `model/video_vae.py` | fp16；encode 用于 ref，decode 用于出帧 |
| Audio | `model/audio_vae.py` | fp32；生成阶段默认 CPU decode，避开 DiT 占满的 HBM |

## 5. 分布式（16 die）

| 主题 | 位置 | 说明 |
|------|------|------|
| 设备绑定 | `generate_worker.pin_rank_die` + `launch_generate.py` | 一进程一 die；父进程**不** import `torch_npu` |
| HCCL | `runtime/dist.py`：`init_hccl` / `warmup_collective` | **先集体通信、后 DiT H2D** |
| Seq Parallel | DiT Attention | 序列维切分，FA 前 gather KV |
| Gather 模式 | `H3_HCCL_GATHER=broadcast`（默认） | 更稳；可选 into/list/chunk |
| TE 激活 | `broadcast_tensor` | 层间同步 |
| Ref 同步 | `_broadcast_ref2va_payload` | rank0 encode → 全 rank |
| 文件屏障 | `H3_SYNC_DIR` + `ready.*` | 规避部分 `dist.barrier` AICPU 问题 |

Compose 绑定 `/dev/davinci0`…`15`，`H3_NPROC=16`，`H3_REQUIRE_WORLD=16`。  
一次生成占用**全部 16 die**，不是 16 路独立服务；API **串行一单**。

## 6. 自研优化清单（按优先级）

### 6.1 正确性

| 优化 | 位置 | 说明 |
|------|------|------|
| NVFP4 `from_blocked` | `ops/nvfp4.py` | 对齐 Comfy `comfy_kitchen`；修 t2va 跑偏 |
| Noise fp32→bf16 | `generate.py` noise / progressive upsample | 对齐 Comfy；声画轨迹更一致 |
| AAC 128k | `generate.py` `write_mp4` | 对齐 Demo SaveVideo |
| t2va 空参考 | `partition.py` + `generate.py` + `generate_worker.py` | 禁止默认金毛图 / TE cache 污染 |
| Ref job 空列表 | `serve_bridge.py` | 防上一单残留 |

### 6.2 性能 / 显存

| 优化 | 位置 | 说明 |
|------|------|------|
| INT8 Cube + NZ pack 一次 | `int8_convrot.py` / `h2d.py` | 避免逐步转置拷贝 |
| FA infer_v2 | `fa_h3.py` | 融合 FA |
| TE∥Ref | `H3_TE_RANK0_ENCODE` | 缩短 encode 墙钟 |
| Audio CPU decode | `generate.py` | DiT 后腾 HBM |
| `empty_cache` | `device.py` + generate/worker 多处 | 任务间 / VAE 前后 |
| Prewarm skip VAE | `H3_SKIP_VAE` + worker | 常驻预热不占 decode 显存 |
| Spawn stagger | `H3_SPAWN_STAGGER` | 降低 16 进程同时 `set_device` 失败率 |

### 6.3 可选 / 实验

| 开关 | 位置 | 说明 |
|------|------|------|
| `H3_NPU_TORCHAIR=1` | `runtime/accel.py` | TorchAir compile DiT block（默认关） |
| `H3_PROGRESSIVE` | `generate._parse_progressive` | 多分辨率省峰值显存 |
| `H3_ATTN_RING` | ring attention | 实验路径 |
| `H3_NPU_INT8_FORCE_DEQUANT` | 强制 BF16 回退 | 调试用 |

## 7. 关键环境变量（`H3_*`）

### 部署

| 变量 | 典型 | 含义 |
|------|------|------|
| `H3_PHY_DEVICES` | `0..15` | 物理 die |
| `H3_NPROC` / `H3_REQUIRE_WORLD` | `16` | 进程 / 世界大小 |
| `H3_PARTITION` | `ref2va` | DiT 分区 |
| `H3_MODELS` | `/models/h3_quant` | 权重根 |
| `H3_SERVE` / `H3_SERVE_DIR` | `1` / `…/h3_serve` | 常驻邮箱 |
| `H3_SERVE_PREWARM` / `H3_SERVE_DIT_WARMUP` | `1` | TE+ref / 1-step DiT 预热 |
| `H3_API_PORT` / `H3_JOB_ROOT` | `8080` / `/workspace/jobs` | API |
| `H3_TASK_TIMEOUT` | `7200` | 单任务超时秒 |

### 推理

| 变量 | 典型 | 含义 |
|------|------|------|
| `H3_NPU_INT8_NZ` | `1` | NZ pack |
| `H3_FA_BACKEND` | `infer_v2` | FA |
| `H3_HCCL_GATHER` | `broadcast` | gather |
| `H3_SAMPLER` | `res_multistep` | 采样器 |
| `H3_PROGRESSIVE` | `0` | 分辨率 schedule |
| `H3_STEP_SYNC` | `1` | 每步 sync（真实墙钟） |
| `H3_TE_RANK0_ENCODE` | `1` | TE∥ref |
| `H3_SKIP_WARMUP` | `1` | 跳过额外 warmup forward |
| `H3_TASK` | `t2va`/`ref2va`/`auto` | 任务模式 |

## 8. 耗时统计（metrics.json）

### 写入

1. `run_generate` 创建 `runtime/metrics.py`：`MetricsLog`
2. 关键 tag：`start` → `dit_loaded` → `te_encoded` → `refs_encoded` → `step_1..N` → `dit_done` → `vae_decoded` → `audio_decoded` → `video_written`
3. 每条含 `elapsed_s`、NPU/Host 内存快照；step 带 `step_s`；VAE 带 `vae_s`；`dit_done` 带 `request_s` / `avg_step_s`
4. **仅 rank0**：`metrics.dump(output.metrics.json)`（与 `output.mp4` 同目录）

### 分析

```bash
# 单次
python3 scripts/analyze_metrics.py --metrics /path/to/output.metrics.json --out-dir /tmp/report

# 矩阵压测（拉容器内 metrics + 汇总表）
python3 scripts/bench_ref_matrix.py --only all
# 结果：tmp/bench_npu_v1.1/summary.md
```

API **不**解析 metrics；Gateway 只看 `progress.json` 与任务状态。

## 10. 与 Comfy / Demo 对齐关系

| 能力 | Comfy / Demo | 本栈 |
|------|--------------|------|
| 节点 | `MiniMaxH3ReferenceToVideo` | `partition` + `generate` |
| 权重 | 同名 Ref2VA INT8 + NVFP4 TE + VAE | 同文件挂载 |
| 零参考 | 允许空 ref | `task=t2va` / auto 无参考 |
| Prompt 标签 | presentation 前缀 + 正文赋职 | `format_ref2va_prompt_multimodal` |
| 噪声 / AAC | fp32 randn；AAC 128k | v1.1 已对齐 |
| TE scale | `from_blocked` | v1.1 已对齐 |

数值无法与 GPU 逐样本一致（INT8 累积、FA 实现差异），但同 prompt/seed/分辨率下内容与听感应接近。
